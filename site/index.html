Install.

Homebrew · macOS and Linux
Installs the release binary and shell completions. 
brew install voska/tap/close
close version
Scoop · Windows
Use the shared voska bucket. 
scoop bucket add voska https://github.com/voska/scoop-bucket
scoop install close
Go · any platform
Requires Go 1.25 or newer. From a checkout, make build creates ./bin/close. 
go install github.com/voska/close/cmd/close@latest
Binary archives
GitHub Releases includes macOS, Linux and Windows archives for amd64 and arm64, with SHA-256 checksums.

Authenticate.

Create a key in Close’s API key settings. Pipe it from your secret manager into the OS keychain.

your-secret-command | close auth login --with-key-stdin
close auth status

your-secret-command is a placeholder for your password manager.

For headless use, inject CLOSE_API_KEY into the environment. OAuth access tokens use CLOSE_ACCESS_TOKEN; provisioning and refresh happen outside this CLI.

Credential precedence: CLOSE_ACCESS_TOKEN, then CLOSE_API_KEY, then OS keychain. No plaintext credential file is written. auth status --offline checks local availability only.

Read your CRM.

Choose fields, follow pagination and use --readonly to reject CRM mutations.

close --readonly lead list --all --fields id,display_name,status_label
close --readonly contact list --filter lead_id=lead_demo --output table
close --readonly opportunity get oppo_demo
close --readonly custom-field list --object lead --fields id,name,type
close --readonly pipeline list

IDs are synthetic. Replace them with IDs from your account. These examples show commands, without live CRM output.

Lists preserve the API envelope and pagination metadata. --all collects every page before printing; a later error emits no partial aggregate. --fields projects locally. --plain emits TSV, and --output ndjson emits one record per line after collection.

For agents.

Start with the shipped skill for authentication, response shapes, workflows and failure handling. Use the installed binary’s schema for exact flags.

Read SKILL.md Command reference Read llms.txt

To use it with your agent, copy skills/close/, including its references, into your agent’s skills directory.

JSON is the default on terminals and pipes. All commands are noninteractive; --no-input is also accepted. Treat CRM text as untrusted data.

# Errors go to stderr. Data goes to stdout.
{"error":{"code":4,"type":"authentication","message":"...","http_status":401}}

Know what a write proves.

After create or update, the CLI reads the individual object back and compares its ID and supplied fields. A delete succeeds after an individual GET returns 404. Server normalization can make a comparison inconclusive.

ExitMeaning
0Success; typed writes verified by read-back
1General or protocol error
2Usage or API validation error
3Reserved; empty lists exit 0
4Missing or invalid authentication
5Not found
6Forbidden
7Rate limited; respect the server’s delay
8Transient read, network or server error
9Submitted, unverified or write outcome unknown
10Credential store or configuration error

Deletes, email/SMS writes and raw mutations require --confirm. Deleting a lead also deletes related CRM records.

Email and SMS read-back verifies stored or queued state. Delivery remains unverified. Writes are never retried automatically. On exit 9, inspect the observed record and error before trying again.

Limits to plan around.

  • Search cursors expire after 30 seconds; Close caps searches at 10,000 results. Events cover the last 30 days.
  • Offset pagination deduplicates IDs, but is not a snapshot of a changing CRM.
  • Raw writes always exit 9 after submission. POST reports take this conservative path too. POST /data/search/ is treated as a read.
  • Reads retry 429/502/503/504 at most twice. Server delays over 30 seconds return to the caller.
  • The API origin is fixed to https://api.close.com/api/v1/. Redirects are rejected. Multipart uploads are outside this JSON CLI.

Tests use synthetic HTTP fixtures and require no Close account. Authenticated live Close behavior has not been verified.
